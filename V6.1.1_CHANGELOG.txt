HUB OF ASPIRANTS — V6.1.1
SERVICE / DATA-LAYER SEPARATION
================================

BASELINE
--------
Built directly from the verified working HOA V6.1.0 Feature-Separated deployment root.
Existing CSS separation, feature separation, section navigation and user workflows are preserved.

CHANGES
-------
1. Added shared service foundation:
   js/services/base.js
   - Supabase client access
   - authenticated-user helper
   - RPC helper
   - Edge Function helper
   - Storage helper

2. Added domain services:
   js/services/student-service.js
   js/services/test-service.js
   js/services/course-service.js
   js/services/result-service.js
   js/services/content-service.js
   js/services/storage-service.js
   js/services/admin-service.js

3. Migrated the main application data paths to the service layer, including:
   - student registration insert
   - student profile retrieval/deletion
   - admin authentication/verification
   - admin password update
   - candidate password/access/reset operations
   - result-history retrieval
   - attempt creation
   - secure test submission
   - test save/delete/update
   - attempt review retrieval
   - Admin session checks

4. Updated js/supabase.js so student loading delegates through the Student service.

5. Service scripts are loaded before feature modules so future feature migration can occur without changing the application entry architecture.

COMPATIBILITY
-------------
No section-navigation redesign was made.
No database schema changes were made.
No Supabase RPC names or payload contracts were changed.
Existing global functions remain available as compatibility entry points.

INTENTIONALLY DEFERRED
----------------------
Some legacy feature modules still contain direct Supabase calls. They are left in place for controlled migration in the next separation stage rather than risking the verified working section flow.

- No page CSS <style> blocks remain; external CSS remains authoritative.
- All local js/css/assets references resolve to existing files.
